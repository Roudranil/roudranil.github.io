# Quirks

Things that will surprise a cold read of the codebase.

- **Site title is `"rudy"`**, not "roudranil" — `src/config.ts:7`. Shows in `<title>` and the shell-prompt-styled header branding (`[rudy ~]$`). Grepping for "roudranil" in `src/` will mostly miss branding strings.
- **`@config` resolves to a single file**, not a directory (`tsconfig.json:9-16`). `@utils` has no bare mapping — always import as `@utils/<file>` (e.g. `@utils/toc`).
- **Nav labels are shell-prompt styled** (`~/about`, `~/posts`, etc. in `src/config.ts` `MENU`), but `Header.astro:42-47` matches the *active* nav item by stripping to the last `/`-segment of the *path* (`menuItem.path.split("/").pop()`), not the label. The label string and the matching logic are two separate things that must stay in sync by convention, not by type.
- **`buildTOC` (`src/utils/toc.ts`) has a hardcoded assumption baked into a comment**: markdown bodies are assumed to start at `h2`, because `h1` is reserved for the layout-injected page title. Changing that assumption requires editing the literal `2` in the function.
- **Heading text passed to `buildTOC` always carries a trailing literal `#`** — `rehype-autolink-headings` appends the anchor as a text child of the heading before Astro's `getHeadings()` collects it (`astro.config.mjs`). `buildTOC` strips it (`stripTrailingAnchor`); if you add another consumer of raw `MarkdownHeading.text`, it needs the same strip or it'll show a stray `#`.
- **The server-rendered ToC heading text is a fallback, not the real content** — see `docs/aesthetic.md`'s "Table of Contents as `tree` output" section. `TableOfContents.astro`'s script overwrites it client-side from the real heading's `innerHTML` on `astro:page-load`. `ClientRouter` is active (`BaseLayout.astro`), so any new ToC-adjacent script must hook `astro:page-load`, not `DOMContentLoaded` — the latter does not fire on client-side navigations.
- **Collapse-animation via transitioned `grid-template-rows` needs Chrome 117+/Safari 17.4+/Firefox 127+**; older browsers collapse/expand instantly with no animation. This is accepted, not a bug to fix.
- **`.toc-cont` (`TocLevel.astro`) is positioned with `top: 1lh`, not a pixel value** — `1lh` needs Chrome 120+/Safari 16.4+/Firefox 120+, same era as the `grid-template-rows` note above. It has to stay a line-height unit: the gutter's `.toc-glyph` span is what gives the row its height (in flow, one line), and `.toc-cont` must start exactly one line below it and be positioned out of flow — otherwise the continuation lines inflate the row themselves, which is what happened the first time this was built (8 stray `│` lines under every heading, because `overflow: hidden` had nothing to clip against once the clipped content was itself sizing the box).
- **Never put whitespace — including a plain newline/indent — between the children of an element with `white-space: pre`** (`.toc-gutter`, `TocLevel.astro`). Outside `pre` contexts, whitespace-only text nodes between tags collapse to nothing; `white-space: pre` disables that collapsing, so each one survives as a real preserved text run. With `display: block` glyph/continuation children, that run becomes its own anonymous block box — an invisible blank line — pushing the "real" line down and inflating the row's height by one line per stray whitespace run. This is why every child of `.toc-gutter` is written on a single unbroken source line with zero space between tags, and why `{prefix}{GLYPH}` must be built as one variable and rendered as a single `{expr}`, not split across two JSX lines.
- **ToC toggle state must be read from `data-expanded`, never from `getComputedStyle(...).visibility`** — the collapse transition makes computed style unreliable mid-animation, and `querySelector` without a `:scope > ` child combinator (or a same-name CSS rule without a child combinator) will read a *descendant* level's panel instead of the clicked level's own.
- **Dead code deliberately left in place**: `Header.astro:14-26,32,99-101` and (per earlier exploration) `Socials.astro` carry commented-out alternate implementations (unused logo SVG, cursor-blink animation, alternate title-underline gradient). These are not cleanup targets unless explicitly asked — per repo convention (`.claude/rules/common/coding-style.md`), pre-existing dead code gets flagged, not silently deleted.
- **`about.md`/`contact.md` bypass the content-collection system entirely** — they're plain `src/pages/*.md` files using `layout:` frontmatter, while `posts`/`projects` go through Zod-validated collections. Two coexisting authoring patterns for what look like similar "static page" needs; this is historical, not a rule to follow for new page types.

See `build-and-deploy.md` for scripts that were intentionally deleted (`release.sh`, `version.sh`, old `sync-version.sh`) — don't resurrect references to them.

- **`astro dev` does not hot-reload `astro.config.mjs`, nor any module it imports** (e.g. `src/plugins/expressive-code-language-badge.mjs`). Editing the Expressive Code plugin and expecting the running dev server to pick it up silently fails — it keeps serving output built from the old module. Run `npx astro dev stop` then restart `npm run dev` after any change to `astro.config.mjs` or its imports.
- **Nerd Font icon glyphs must be entered as `\uXXXX` escapes in source, never as literal pasted characters** — see `LANGUAGE_ICONS` in `src/plugins/expressive-code-language-badge.mjs`. Private-use-area codepoints (the range Nerd Fonts patches icons into) are effectively invisible/non-printable in most text encodings and editing tools; a literal pasted glyph can silently vanish on write, leaving an empty string with no error. Always write the explicit `\uXXXX` escape and verify with a bare Python `ord()` check (or similar) that the codepoint actually landed, rather than trusting what an editor renders. The Footer's `branchIcon` (`src/components/Footer.astro`) is currently a **placeholder** codepoint (`U+E725`) — swap it for the actual desired glyph when given one, same `\uXXXX`-escape rule applies.
- **`src/utils/git.ts` anchors paths to `process.cwd()`, not `import.meta.url`** — during `astro build`, Astro copies this module into `dist/.prerender/` for the SSR prerender step, so `import.meta.url` inside it resolves to a path under `dist/`, not the real source tree. Any code here that needs the repo root (to run `git` commands, or to read/write `src/data/last-edited-cache.json`) must use `process.cwd()` instead — `npm run dev`/`npm run build` are always invoked from the project root, so this is reliable. Don't "fix" this back to `import.meta.url`-based resolution; it looks more correct but breaks under the actual build.
- **`src/data/last-edited-cache.json` is a self-healing fallback, not hand-maintained data** — it only gets consulted when a real `git log -- <file>` call for that file comes back empty (untracked file, or a shallow/incomplete checkout). Any build with full git history overwrites stale entries automatically. Don't manually edit dates in it expecting them to "correct" what's shown — if git has real history for the file, the cache is ignored entirely in favor of the live lookup.
